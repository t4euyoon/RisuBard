# 플러그인 조회 성능 및 BardWiki 자동 제공 설정

## 최종 적용

- 캐릭터 스냅샷은 전체 DB가 아닌 요청한 캐릭터만 복사한다.
- BardWiki 호환 문맥 선택은 필요한 최근 구간만 역방향으로 탐색한다.
- 전체 객체 재귀 비교·재사용 저장은 측정에서 느려져 실제 저장 경로에서 제거했다.
  `pluginSnapshotExperiment.ts`는 비교 실험에만 사용되며 제품 코드에서 호출하지 않는다.
- 설정 → 플러그인의 각 API V3 항목에 **BardWiki 문맥 자동 제공**을 추가했다.
  기존·신규 플러그인 모두 기본 꺼짐이며, 켜면 다음 조회부터 자동 문맥을 제공한다.
  같은 이름의 플러그인 업데이트/덮어쓰기 시 사용자 선택을 유지한다.
  삭제 후 새로 설치하는 경우 기본 꺼짐으로 돌아간다.
- `getCharacter`, `getChar`, `getCharacterFromIndex`, `getChatFromIndex`,
  캐릭터를 포함하는 `getDatabase`에 동일하게 적용한다.
- 명시적 `bardWiki.getContext()`는 별개로 작동한다. 이 설정은 데이터 접근 차단 권한이 아니다.
- API 선택 인자와 Asset Maid 전용 패치·생성 스크립트를 제거했다.
  원본 Asset Maid 0.9.8을 그대로 사용한다.

자동 제공을 끄면 원본 저장 데이터는 반환하지만 가상 BardWiki 메모리는 추가하지 않는다.
자동 제공에 의존하는 플러그인은 사용자가 켜야 한다. 일반 채팅용 BardWiki는 그대로다.
API V2에는 원래 이 자동 주입 경로가 없으므로 설정을 표시하지 않는다.

## 검증

[성능 비교 보고서](asset-maid-performance-comparison.md)의 합성 데이터 비교를 기준으로
공통 개선 두 개를 유지하고 객체 재사용을 철회했다. 원본 사용자 DB/OCI에서의 전체
분석·이미지 생성·삽입 시간은 아직 측정하지 않았다.
설정 기본값, 플러그인별 독립성, 즉시 반영, 업데이트 보존, 조회 주입 여부와 UI 토글을 테스트한다.
Docker 이미지를 배포한 뒤 브라우저에서 새 프런트엔드를 불러와야 설정을 사용할 수 있다.
